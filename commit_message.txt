⚡ Bolt: [performance improvement] Provide stable EMPTY_ARRAY reference for Zustand selectors

💡 What: The optimization implemented
Created a stable `EMPTY_ARRAY` reference in `web-ui/src/constants/common.ts` and used it instead of inline array literals `[]` as fallbacks in `MessageList.tsx`, `QueueBar.tsx`, and `SessionsSidebar.tsx` Zustand selectors.

🎯 Why: The performance problem it solves
Returning inline array literals (e.g., `?? []`) inside Zustand selectors creates a new array reference on every invocation. Since `[] === []` evaluates to `false`, React thinks the selector result has changed, causing the component to re-render on *every single store update* even if the fallback was still an empty array.

📊 Impact: Expected performance improvement
Significantly reduces unnecessary re-renders in `MessageList`, `QueueBar`, and `SessionsSidebar` when their respective arrays are empty. The components will now bypass re-rendering if other state changes occur in the store but the underlying targeted slice stays empty.

🔬 Measurement: How to verify the improvement
Use React Developer Tools Profiler and record a session while the chat store updates (e.g. streaming a response in another session while a blank session is selected, or updating toast notifications). `MessageList` and `QueueBar` will no longer show up as rendering on every tick due to `hook 1 changed`.
